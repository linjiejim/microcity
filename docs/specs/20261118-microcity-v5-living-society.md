## 1. 背景与目标

v0–v4 做成的是“一条停电通知的传播实验室”：生活是背景板，所有结构都焊在停电上（`OutageEventSpec`、`OutageStats`、南北供电区、七阶段漏斗）；人按 21 个写死的职业排日程模板；三维是固定角度的正交相机加程序生成的方块。

用户的要求（2026-11-18）：
- 更生活化的场景，更立体真实的三维；
- 可以跟随某个角色，可以倍速回放角色的一天；
- 每个角色有工作与休息、社会关系、兴趣爱好、物品、经济活动；
- 有社会画像，有多个社区可选；
- 有具体的影响案例，宏观和微观都能看；
- 可以定制组合场景和社会组成，做社会实验；
- 直观、易用、美观、精确。

定位改成：**一个可以暂停、倒带、分叉的小社会**。生活是基线，实验是扰动：没有任何事件时，这个社会本身就值得看；任何实验都是“同一个随机种子的两个平行世界”之间的差。

目标：
1. 打开就是一个在过日子的社区，不需要先填表。
2. 点任何一个人，能跟着看完一天，并且每一步都能问“为什么”。
3. 同一个种子永远得到同一个世界；一个链接就能复现某一刻。
4. 不需要服务器，不需要密钥就能用；填了密钥才有模型能力，花费看得见。

### 2.2 内核：一个人是什么

| 层 | 内容 | 怎么起作用 |
| --- | --- | --- |
| 身份 | 年龄、家庭、人生阶段（儿童 / 学生 / 在职 / 持家 / 退休 / 待业） | 决定有哪些固定承诺 |
| 职业 | 职业表里的一行：班次、工资、工作地类型 | 班次是硬约束；本社区岗位不够的人去“城里上班”，从公交站离场 |
| 需求 | 饥饿、精力、社交、娱乐，0–1，按活动种类线性升降 | 闭式计算，不逐秒发事件；需求越缺，对应活动的效用越高 |
| 时间 | 固定承诺 + 自由时间 | 每当手头的事做完，就选下一件：先看有没有承诺到点，没有就按效用选 |
| 关系 | 家人、伴侣、朋友、同事、同学、邻居、熟人；亲密度与信任 | 同处一地会聊天，聊天涨亲密度；反复同场的陌生人变熟人，熟人变朋友；久不见面会淡 |
| 兴趣 | 2–4 个标签（下棋、广场舞、喝茶、打球、看书、散步、游戏、看电视……） | 决定休闲去哪、和谁碰上 |
| 物品 | 耐用品（手机、电动车、电视……）、随身物、家里的存粮与日用品 | 电动车让出行更快；没电视就没有“看电视”这个选项；存粮见底就得去买菜 |
| 经济 | 个人钱包 + 家庭账户；工资、养老金、零花钱；吃饭、买菜、房租、水电、娱乐 | 手头紧的人更愿意在家吃、选不花钱的消遣 |
| 内心 | 心情（由需求与当天经历算出）、每日小结 | 画像与回放用 |

**选择怎么做**（沿用 v0 的原则，范围从“对新闻的反应”扩大到所有自由选择）：
- 每个选择点生成候选（做什么、去哪、和谁）；
- 每个候选的效用 = 需求缺口 × 活动的回报 + 兴趣 + 时段习惯 + 同伴 − 路程 − 花费（手头越紧越重）− 天气；
- 用 softmax 抽样，随机数的键是（人、选择点序号）；
- 写成 `decision` 事件：候选、各项因子、概率、选中的那个。

**世界**：
- 地图是格子（一格 4 米）：街道、小路、广场；建筑占若干格，有门、有楼层、有住户单元。
- 每栋建筑的室内由“室内模板”给出：房间大小、家具、**站位**（床、座位、灶台、柜台、工位……）。内核按站位安排人，三维层按同一份模板画家具，所以看到的位置就是模型里的位置。
- 天气按天抽样（晴 / 阴 / 雨），雨天户外活动的效用下降。

**经济**（钱守恒是不变量）：
- 账户：每个人、每个家庭、每家店、一个“外部”账户（城里的雇主、批发商、财政、不住在这里的房东）。
- 店铺：商品有价格、库存、进货成本；员工按班次上班，每周五发薪；店主每周提走利润。
- 家庭：发薪日成员把一部分收入交到家庭账户；家庭账户付房租、水电、买菜；个人钱包付外食、消遣、个人物品。
- 所有账户（含外部）之和恒等于初值。

### 2.3 内核：结构

```
packages/society/src/
  core/        rng、pq、time、hash（从旧内核复制）
  model/       类型：社区定义、状态、事件
  params.ts    规则参数（需求速率、效用权重、经济常数），带版本
  world/       地图与寻路、室内模板与站位
  community/   社区包（规格）、人口合成、布局生成、名字
  engine/      时钟核心：任务队列、发事件、系统注册
  systems/     daily（承诺与下一步）、needs、economy、social、weather、summary
  reduce.ts    同构 reducer：状态只由事件改变
  checks.ts    不变量
  metrics/     时间利用、收支、关系网的汇总
```

- 引擎核心只管时间和任务队列；每个系统声明自己处理的任务、自己监听的事件。
- 人的行为是“做完一件选下一件”的状态机，不做整天的计划再修补：承诺是硬约束，其余由效用决定。这比旧版的日程模板简单，也更稳。
- 位置轨迹、活动、需求都能从事件闭式算出任一时刻的值，所以回放可以任意拖动、任意倍速。

### 2.4 应用：纯浏览器

```
apps/studio/src/
  sim/         Web Worker：按天推进内核，逐天把事件和午夜快照发给主线程
  timeline/    把事件整理成每个人的轨迹段与活动段；任一时刻的视图状态
  world3d/     立体世界（命令式 three.js）：建筑、室内、角色、光影、镜头、后期
  hud/         顶栏、底部时间轴、人物卡、名单
  settings/    密钥、模型预设、用量
  llm/         OpenRouter 直连、预算闸、缓存
  theme/ ui/   v4 的颜色、图标、组件
```

- **先算后看**：进入一个社区，Worker 用几秒把若干天算完；之后的“观看”全是回放。“直播”只是回放停在最新时刻。
- **表现层只读**：三维层拿到的是事件（几点从哪走到哪、在哪个站位做什么），自己做插值、朝向、动画，永不回写内核。

### 2.5 立体世界

走**精致微缩模型**路线，不追写实：

- **建筑与角色先用程序化套件**：墙、屋顶、门窗、招牌、家具都由代码生成，角色是带四肢的玩偶，动作（走、坐、吃、工作、聊天、睡、跳舞、骑车）由程序生成。原因：室内剖面需要完全控制每一面墙和每一层楼；不依赖外部资产的下载与授权；包体小。套件留有接口，以后可以换成 glTF 模型。
- **镜头四档**：社区鸟瞰 → 街道 → 跟随某人 → 室内剖面（被跟随的人进屋时，上面的楼层和朝向镜头的墙淡出）。
- **光影**：太阳随时间走，柔和阴影，环境光遮蔽，夜晚窗户和路灯亮起并有辉光，移轴景深，暗角。
- **好看的东西都是真的**：窗亮表示家里有人醒着；店里的人数就是模型里的人数；雨天是模型里的雨天。
- **跟随视角**的界面只有：需求条、此刻在做什么和为什么、钱包变动、关系事件。“为什么”一点就展开候选与效用。
- **回放一天**：底部一条按活动着色的时间轴，可拖动；倍速 1× 到 600×；“一分钟看完一天”的自动导演在睡觉和上班时快进，在聊天、花钱、做选择时放慢。

### 2.6 模型：自己的密钥，直连 OpenRouter

- 不填密钥，一切照常：规则心智、回放、画像都不需要模型。
- 设置里填 OpenRouter 密钥，只存在本机浏览器（localStorage），只发给 `openrouter.ai`。
- 两个模型分开选，各有预设，也可以从 OpenRouter 的模型列表里换：

| 用途 | 预设 | 说明 |
| --- | --- | --- |
| 决策模型 | `typesafe/jev-1.13` | 只回答语义因子，不生成文本；M4 接入内核的选择点 |
| 语言模型 | `deepseek/deepseek-v4-flash` | 只负责表达：被跟随者的内心独白（M2）、对话、报告（M4） |

- **用量看得见**：设置里显示本机累计花费（每次调用的 token 与金额）和账户侧的用量与额度（OpenRouter 的密钥查询接口）；本机有预算闸（默认 $0.5），超了就停，并说明原因。
- 语言模型只能复述事实表里的内容（沿用 v1 的报告原则）；答案按（模板版本、模型、事实表哈希）缓存在本机。

### 2.7 画像、社区、实验（M3–M5，只定方向）

- **画像**三层：个人（作息环、关系网、账本、物品、心情曲线）、群体（按年龄、职业、收入分组）、社区（人口金字塔、收入分布、时间利用、网络结构、资金流向、场所热度）。画像既是配方也是体检。另有一页校准：模型与现实的典型事实对照。
- **社区包**是纯数据。首批：老城街坊（M1 就有）、通勤新小区、城中村、大学城、工厂镇。
- **干预**取代停电事件规格：信息、环境、经济、制度、人口五类；停电是其中一种。
- **微观镜头**：同一个人在两个平行世界里的同一天并排放，标出差异。
- **实验台**：选社区 → 组合干预 → 选指标和要跟的人；实验清单、预测判定、先猜再跑沿用。
- 旧的五条结论在新内核上重跑，看它们在更丰富的社会里还成不成立。

### 2.8 M3–M5 的细化（2026-11-19 开工前补）

**M3 画像**

- 数据：Worker 逐天把事件累积成紧凑的统计（每人每天的小结、分时段的场所人数、资金在各类账户之间的流向、关系数），主线程一次取回；不需要把所有事件搬到主线程。
- 三层：
  - 个人（人物卡里的“这个人”页）：24 小时作息环、这些天的心情与收支、关系圈。
  - 群体：按人生阶段分组，比时间利用、收支、聊天、心情。
  - 社区：人口金字塔、家庭类型、收入分布与基尼系数、时间利用、关系网的构成与孤立的人、钱从哪来到哪去、各类场所一天里的人数。
- 校准：模型的时间利用与一份现实参照并排，差多少直接写出来，并注明参照的出处与口径差异。只做对照，不为了对上而调参。
- 社区日报：每天一页，从统计里挑出天气、最热闹的地方、新认识的人、花销，全部来自事实，不用模型。

**M4 实验台**

- 干预是对世界规则的补丁，有起止日期：

| 类型 | 做什么 | 例子 |
| --- | --- | --- |
| 停业 | 某个地点在这段时间关门 | 菜市场搬走了 |
| 调价 | 某家店某种商品的价格乘一个系数 | 菜价涨三成 |
| 发钱 | 给每户（或某类家庭）一笔钱 | 消费券 |
| 裁员 | 某个单位裁掉一部分人 | 工厂裁员一半 |
| 房租 | 房租乘一个系数 | 房租涨两成 |
| 开伙 | 某个地点开始卖饭，定一个价 | 活动中心办社区食堂 |
| 天气 | 这段时间都是某种天气 | 连下一周雨 |
| 传言 | 一条消息从几个人开始传开，知道的人多囤东西 | “菜要涨价了” |

- 信息系统先做最小版：一条消息只有“知道 / 不知道”，经聊天传播，知道的人行为被修正。完整的主张、转述变形、信念与信任迁移不在这一期。
- 实验 = 同一个社区、同一批种子下，基线与干预两条世界线。指标从每日小结与资金流里算，判定沿用旧规则：逐种子配对，方向在不少于七成的配对里成立算“支持”。
- 先猜再跑：跑之前先让人选预期的方向；结果页先给判定，再给分布。
- 微观镜头：按“这一天过得多不一样”给人排序，点开是同一个人同一天在两条世界线里的时间轴并排，加上钱、聊天、心情的差。
- 决策模型先作为“第二意见”：对某一次选择，把同样的候选交给决策模型判断，与规则的概率并排显示；不改世界。

**M5 多社区**

- 一个布局骨架、四个配方：老城街坊、通勤新小区、城中村、工厂镇。配方决定人口构成、住楼的比例、本地岗位与去城里的比例、有哪些店、车间多大。
- 组合器：从一个配方出发拖参数，旁边实时显示“配方画像”（人数、户数、年龄结构、岗位）；生成即进入。
- 对话建镇：一句话交给语言模型，换回对规格的补丁；只接受白名单字段，规范化后说明改了什么。
- 影响案例：实验清单的预设，现场运行，不存预先算好的数字。
- 分享：链接里编码社区规格与实验清单。

## 3. 里程碑与验收

### M0 样片（去风险）

- [x] 一个街区：住宅、店铺、街道、树、路灯，日夜光影，移轴景深。
- [x] 一个可跟随的角色：走路、进屋，镜头跟随；进屋后出现室内剖面。
- [x] 内核性能探针：约 180 人 × 30 天，在 Node 里 10 秒内算完。（实测约 3.5 秒）
- [ ] 画面截图交给用户看；不认可就换美术方向，不带着它往后走。（截图已出，等用户看）

### M1 生活内核

- [x] 老城街坊：约 180 人，按规格确定性生成；同规格同种子逐事件相同。
- [x] 工作日与周末的作息不同；有班次的人按时上下班；有人去城里上班。
- [x] 钱守恒；库存不为负；没有人同时在两个地方；没有两个人占同一个站位。
- [x] 关系会变：30 天内有新的熟人和朋友出现。
- [x] 重放一致：事件流经 reducer 重建的状态与引擎内状态的哈希相同。
- [x] 典型事实检查：人均睡眠 6.5–9.5 小时；在职者工作日工作 6–10 小时；没有人连续两天不吃饭；月末没有家庭破产（账户为负）超过一成。
- [x] 每个自由选择都有 `decision` 记录：候选、因子、概率、选中项。

### M2 世界与跟随

- [x] 打开应用，几秒内看到在过日子的社区；不需要服务端。
- [x] 四档镜头可切换；点人即可跟随；进屋自动剖面。（俯瞰、街道、跟随三档由按钮切换，室内剖面在跟随时自动出现）
- [x] 人物卡：需求条、此刻在做什么与为什么、钱包、今天见了谁；可展开候选与效用。
- [x] 底部时间轴：按活动着色，可拖动到这一天的任一时刻；倍速与“一分钟看完一天”。
- [x] 设置：密钥、两个模型的预设与更换、本机用量与账户用量、预算闸；不填密钥不影响使用。

## 4. 决定

- **D62 定位改为“活的小社会”：生活是基线，实验是扰动。**
  原因：用户要生活化；而且有了可信的基线，任何干预都能表达为同种子平行世界之差。
- **D63 不带包袱：新内核与新应用放在新目录（`packages/society`、`apps/studio`），旧代码（`packages/sim`、`apps/server`、`apps/web`）原样保留到 M4 接替其功能后删除。**
  原因：演示站与已有实验在此期间继续可用；旧代码打标签 `v4-classic` 留档。
- **D64 人的行为是“承诺 + 需求驱动的下一步”，不做整天的计划再修补。**
  原因：更简单、更稳，干预下的行为变化自然出现，不需要专门的改计划逻辑。
- **D65 职业、活动、兴趣、商品、室内都是数据表，不是枚举加硬编码时间表。**
  原因：多社区和用户定制都靠换数据。
- **D66 需求、位置、关系的淡化都用闭式计算，状态仍只由事件改变。**
  原因：事件量可控（约 180 人 × 30 天几十万条），回放可任意拖动。
- **D67 钱守恒：设一个外部账户承接社区外的收支，所有账户之和恒定，作为不变量。**
- **D68 站位由内核分配，室内模板是内核与三维层共用的一份数据。**
  原因：“精确”要求看到的位置就是模型里的位置。
- **D69 规则模式在浏览器的 Web Worker 里跑；去掉服务端。**
  原因：即开即跑，演示站变成静态站，不再有限流与服务器成本。
- **D70 先算后看：一次算完若干天，观看全是回放。**
  原因：拖动、倍速、回看都变得免费；跟随与回放是同一件事。
- **D71 模型由用户自己的 OpenRouter 密钥直连；密钥只存本机，只发往 openrouter.ai。**
  原因：没有服务端可以代管密钥；用户要求。风险：密钥在浏览器里，设置页写明，并建议在 OpenRouter 侧设额度。
- **D72 决策模型与语言模型分开选；预设 `typesafe/jev-1.13` 与 `deepseek/deepseek-v4-flash`（旧版已在用、已核实）。**
- **D73 用量双重可见：本机逐次记账 + 账户侧查询；本机预算闸默认 $0.5。**
- **D74 美术走精致微缩模型，不追写实。**（用户确认）
- **D75 M0–M2 的建筑与角色用程序化套件，不引入外部模型资产；保留更换接口。**
  原因：见 2.5。这一条与讨论时说的“glTF 套件”不同，是落地时的调整；M0 的截图是它的验收。
- **D76 三维层用命令式 three.js，不用 react-three-fiber；界面仍是 React。**
  原因：实例化的角色与逐帧动画、剖面、后期都需要直接控制渲染循环。
- **D77 表现层只读事件，永不回写内核。**
- **D78 规模：每个社区 150–300 人。**（用户确认）
- **D79 M0–M2 只有规则心智；决策模型在 M4 接入选择点，接口先留好。**
  原因：M0–M2 的风险在美术和生活内核，不在模型。
- **D80 旧版演示站在 M2 之前不动；推送与部署照旧先问用户。**（用户确认）
- **D81 v4 的信息减法（D55）继续有效；“三维只从观察页按需加载”（D60）作废，世界本身就是外壳。**
- **D82 街道按 3 倍压缩：画面上一格 4 米，算路程时一格按 12 米（`params.streetScale`）。**
  原因：微缩模型把街道画短了才好看、才装得下；但如果路程也按画面算，全社区走到哪都不到一分钟，“路上”这件事就消失了。按真实街区尺度算时间，最远的一趟约五分钟，是十五分钟生活圈该有的样子。代价：实时（1 倍速）下人走得慢，平时不会用这个速度看。
- **D83 事件留在 Worker 里，主线程按天取：一天 = 这天开始时的状态快照 + 这天的事件。**
  原因：30 天约 40 万个事件，其中决策记录占一半以上的体积；界面任一时刻只需要正在看的那一天。主线程留最近取过的 4 天，拖动与换天都从快照重放。
- **D84 一家人的饭、接送孩子是固定安排，不是自由选择。**
  原因：一起出门、一起到、一起开饭，靠“同一时刻出发、同一速度走”自然对齐，不需要人与人之间的耦合逻辑。
- **D85 链接可以带 `seed`、`t`（如 `D03 18:30`）、`who`：同一个链接看到同一刻。**

- **D86 画像的数据在 Worker 里逐天累积成统计，主线程一次取回。**
  原因：画像要看所有天，而事件只按天留在 Worker 里（D83）。
- **D87 校准只做对照，不为了对上而调参。**
  原因：把模型调到与一份调查相符很容易，但那只是把数字读回来；先把差距摆出来，再决定哪些机制该改。
- **D88 干预是对规则的补丁，有起止日期；不加干预时必须与基线逐事件相同。**
  原因：这样两条世界线的差才只来自干预；随机数按键计算，干预多出的抽样不会让别处错位。
- **D89 信息系统先做最小版（知道 / 不知道 + 行为修正）；因此经典版暂不删除，修订 D63：等完整的信息传播在新内核里重做之后再删。**
  原因：旧版的主张、转述变形、信念与信任迁移是它的研究核心，这一期不重做就不该说“接替”了。
- **D90 判定规则沿用旧版：逐种子配对，不少于七成同向算支持，不到三成算相反，其余算不明确。**
- **D91 微观镜头自动找“这一天过得最不一样”的人，而不是让用户自己翻。**
- **D92 决策模型这一期只做“第二意见”，不改世界；D79 里“M4 接入选择点”收窄为此。**
  原因：让决策模型参与每一次选择需要异步的引擎，而“先算后看”（D70）靠的是同步算完；并且没有真实密钥可以验证效果。第二意见能让人看到两种心智在同一次选择上的分歧，是接入前该有的一步。
- **D93 多社区用一个布局骨架、四个配方；大学城不做。**
  原因：区别社区的主要是人口、岗位与店铺的构成；大学城需要宿舍、课表这些新的生活系统。
- **D94 对话建镇只接受白名单字段的补丁，再过规范化，并把调整告诉用户（沿用 v1 的原则）。**
- **D95 影响案例是实验清单的预设，现场运行；实验记录仍按预注册流程另写。**
  原因：新内核几秒就能跑完一组对照，不需要像旧广场那样存结果；存了反而会和代码不同步。
- **D96 分享链接把社区规格与实验清单编码在地址里；密钥永远不进链接。**
- **D100 上线：同一个域名，根路径是落地页，`/app/` 是新版，`/classic/` 是经典版（2026-11-23，用户要求部署）。**
  原因：新版是纯静态的，经典版需要服务端，两者都由现有的 Node 进程按路径提供，Caddy 与 DNS 都不用动。旧链接（带 `?ws=` 等参数的根路径）转到 `/classic/`。落地页放介绍视频。

- **D97 补上缺的日常活动，而不是调参去凑调查（2026-11-23）。**
  校准页显示模型里的人每天“自由支配”比调查多五个小时。缺的是活动本身：睡前洗漱、一个人在家吃饭前要自己做、饭后洗碗、陪小学生写作业、做饭的人上午收拾屋子；去城里上班上学的路上（单程按 35 分钟）原来算进了“工作”。另把“歇着”单独成一桶，校准时归入“生理必需”：调查的“睡觉休息”本来就包括休息。补完之后自由支配仍多约两小时（老城街坊 385 分钟对 236 分钟），无酬劳动仍少一半，留给以后：模型里没有办事、陪护病人、用手机处理杂事这些。
- **D98 预算感与处境：钱怎样变成行为和心情。**
  “手头紧”原来只看钱包余额，绝大多数人都不紧，钱的变化几乎传不到行为上。现在看三件事：余钱能撑几周、每周可支配的收入（收入减去房租、水电、买菜）、是不是刚被裁。心情里扣掉处境分：被裁、余钱撑不过两周。常数取整（`params.ts`，`life_v2`），没有对照现实数据。
- **D99 实验的每个种子换一批人。**
  种子原来只换“过法”，同一批人的性格会被当成结论。第 i 个种子用生成种子 `spec.seed + i` 重新生成社区，第一个种子永远是规格里那一批人（微观镜头看的就是它）。影响案例默认打开；实验台里可以关掉。

## 6. 落地记录

2026-11-19，M0–M2：

- **内核**：和平里 181 人、73 户、12 家单位；30 天约 3.5 秒、约 42 万个事件。`pnpm probe` 打印耗时、不变量与各人群的时间利用。
- **应用**：`pnpm dev:studio`，纯静态；构建后约 290 KB（gzip）。截图在 `docs/assets/v5/`：`app-*.jpg` 是真实模拟数据下的应用，`m0-*.jpg` 是样片页（`/?demo=1`）。
- **测试**：内核 21 项、应用的纯逻辑 13 项、端到端 6 项（`pnpm e2e:studio`）。
- **落地时新增的决定**：D82–D85。

已知不足（按严重程度）：

1. **典型事实还没有对照现实**：睡眠、工时落在合理范围，但持家与退休人群每天十一二个小时的“休闲”里有大量在家歇着，偏高；要等 M3 的校准页对照时间利用调查再调。
2. **角色偏素**：玩偶没有脸和手肘，近看动作僵；白天近景的墙面是纯色。
3. **进出门的过渡**：进屋后从门口走到站位是直线，楼房里是斜着上楼；没有被剖开的楼里看不到人。
4. **事件量**：一天约 1.4 万个事件，其中“歇着”“等着”这类短活动偏多；主线程只留 4 天，够用，但决策记录的体积还可以再压。
5. **真实模型调用没有验证过**：密钥、预算、缓存、校验都只在假的网络下测过；OpenRouter 返回的花费字段是否如预期，要等用户用自己的密钥试一次。
6. **决策模型只能选、还没接入**（D79）；“四档镜头”里的街道档只是拉近的俯瞰，没有贴地的行人视角。
7. **只有一个社区**；儿童独自上学、独自在家这类简化还在。

2026-11-19，M3–M5 与立体世界第二轮：

- **内核**：八类干预（`model/intervention.ts`、`systems/rules.ts`、`systems/interventions.ts`）；每日统计、36 项指标、实验比较（`metrics/`）；四个社区配方（`community/spec.ts`、`layout.ts`）。
- **应用**：三个工作区（世界 / 画像 / 实验台）；社区选择与组合器；贴身视角；分享链接。
- **实验**：七个影响案例按预注册流程跑了两次（第二次换了一批人），25 条假设里两次都支持的 14 条，见 [实验记录](../experiments/20261119-v5-impact-cases.md)。
- **测试**：内核 46 项，应用的纯逻辑 26 项，端到端 11 项。

这一轮新增的已知不足（按严重程度）：

1. **校准页上的差距很大**：和平里 15 岁以上居民每天“自由支配”约 9 小时，调查是不到 4 小时；“生理必需”少两个半小时，“无酬劳动”少一个多小时。口径差异（歇着算休闲、老人多）解释不了这么多：模型里的人家务、个人护理、陪伴照料都做得太少，空出来的时间全成了休闲。这是下一步最该动的地方。（2026-11-23：D97 补了一部分，见下文。）
2. **钱对行为的传导太弱**，心情里没有“处境”的分量（失业、入不敷出）：影响案例里与钱有关的结论，换一批人判定就变。详见实验记录第 6 节。
3. **信息系统只有“知道 / 不知道”**（D89）；经典版因此没有删。
4. **决策模型只做了第二意见**（D92），而且接口只在假的网络下测过；影响案例也只有规则心智。
5. **实验的重复只换运行种子，不换人**；实验记录里已经看到这不够。
6. **立体世界**：角色没有手指与表情变化，走路会滑步；贴身视角在屋里头顶是天；公交车没有人上下车，会穿过路中间的行人；雨没有水花、行人不打伞。
7. **四个社区共用一个街道骨架**，从空中看轮廓相近，差别在建筑与人。
8. **对话建镇只能改规格里的那几个数**，不能加新的地点类型或职业。
