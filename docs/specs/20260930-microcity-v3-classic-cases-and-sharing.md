# MicroCity v3：经典案例与分享

- 日期：2026-09-30
- 状态：done（演示站 https://microcity.linjiejim.com 已上线并验证）
- 依赖：[v2 校准与参数化实验](20260929-microcity-v2-calibration.md)（D35–D44 沿用）
- 范围：
  - 为三个经典案例（狼来了、知沟、传话游戏）补齐机制与指标；
  - 让别人能来做实验：先猜再跑、实验清单、实验广场、公开演示站、开源所需文件。
- 明确不做：账号体系、访客间的实验分享与评论、访客用 Jev、120 人、停电以外的事件
- 实验本身记在 [docs/experiments/20260929-classic-cases.md](../experiments/20260929-classic-cases.md)；本文只写平台改动。

## 1. 背景与目标

用户想做几个案例写一篇文章介绍这个项目，并邀请更多人来做实验。落到平台上有两类缺口：

1. **模型表达不了案例**：
   - 没有“虚惊”（发了通知但没停电），做不了“狼来了”；
   - 没有按人群分组的指标，做不了“知沟”；
   - 转述链只在事件流里，看不到“第几手”。
2. **别人进不来**：
   - 实验只能在本机用 A–D 四个固定分支建；
   - 结论要读实验记录才知道；
   - 没有公开的地方可以试。

目标：案例能在模型里预注册、跑完、判定；任何人不装环境就能在演示站上先猜、再看答案、重跑、改成自己的实验；想深入的人能克隆仓库按模板做实验。

## 2. 设计

### 2.1 虚惊事件（social_v3）

- `OutageEventSpec.mode = 'false_alarm'`：照常通知、派工单，但不断电。
  - 剧本在原定恢复供电的时刻放一个 `reveal`；
  - 引擎发 `false_alarm` 事件（不改状态，只标记真相可见），结算过度调整（为这轮挪的安排整段计入），再裁决信任。
- 信任裁决 `falseAlarmVerdict`：信了通知的见证者，按“为此改了安排 / 没耽误”归入 `false_alarm_costly` / `false_alarm` 两类经历；没听说的不变；如实转述的人不受牵连。
- 分支补丁 `EventPatch.mode`：`false_alarm` / `absent`（这一轮从未发生）/ `outage`。
- `TownSpec.events[].falseAlarm`：设计工作区的剧本里有“虚惊”开关。
- 幅度来自 Jev 信任面板（实验前量出）：信任 −0.13 / −0.09。

### 2.2 经历记忆按次数叠加，并直接影响“照不照做”（utility_v3、params_v3）

- 经历对担心、查证的影响从“只看最近一次”改为“按次数叠加”。依据：面板里“两次虚惊”≈ 两次单独的效应之和。
- 新增 `RuleParams.memory.keep`：每类经历对“照常”的效用加减 = −（面板里“照下次通知做”的概率变化），按 softmax 在 P≈0.75、τ≈0.18 处线性化。
  - 只作用于规则心智（`SemanticAnswer.keepBias`）；
  - Jev 从观察里的过往经历自己判断，不重复加。
- 所有经历类型都用同一个面板的照做变化，保证“虚报 vs 漏报”的比较公平。

### 2.3 标准指标：年龄分组与走样

每轮停电新增：
- 青年（18–29）与老人（60+）各自的知情比例、精确比例、组内半数相信用时、住在停电区的组员里措手不及的比例；
- 差距：老人比青年晚多久过半、青年比老人多知情 / 多知道精确时段（百分点）；
- “信过走样版本”的人数：停电前信过不准确的时段，或丢了地点。

它们进“对照”的“更多指标”，也能写进预测。

### 2.4 先猜再跑、实验清单、实验广场

**预测**（`ExperimentManifest.predictions`）：
- 格式：`{ id, text, metric, a, b, expect: higher | lower | same, tolerance? }`；
- 跑完逐 seed 配对自动判定：方向在 ≥ 70% 的配对里成立为“支持”，≤ 50% 为“不支持”，其余“部分支持”；`same` 看中位差是否小于容差；
- 服务端校验指标键与分支；结果存 `ExperimentResult.predictions`；“对照”顶部显示判定。

**实验清单（JSON）**：
- 一个文件就是一个实验：名字、问题、分支（改通知 / 换参数 / 换镇 / 虚惊）、随机种子、预测；
- 可以导入、导出、复制别人的实验改一改。

**实验广场**：
- 新工作区“广场”（快捷键 G）。卡片包括：经典出处、问题、先让访客猜、揭晓答案与两种心智的判定、“在这里重跑（规则）”、“复制并修改”；
- 内容来自 `docs/experiments/gallery.json`，由 `scripts/lab/gallery.ts` 生成，小镇规格与分支取自案例定义；
- 精选实验按 `gallery:<id>@v<version>` 复用，跑过就不再跑。

### 2.5 公开演示站模式（`MICROCITY_PUBLIC=1`）

- 访客只能跑规则模式。Jev 的结果是预先跑好的，写在卡片里。
- 每个实验最多 10 个随机种子；同时在跑的实验最多 2 个。
- 每个 IP 每小时：实验 10 次、运行 20 次、模型调用 30 次。在反向代理后面按 `X-Forwarded-For` 认客户端。
- 在线运行不自动生成对话台词；建镇对话、报告、独白走总预算。
- 闲置 15 分钟、没人连着的运行，存快照后从内存卸下。
- 访客的实验与运行 48 小时后删除，连同分叉出的运行；精选实验保留。
- 服务端直接提供构建好的前端（`MICROCITY_STATIC_DIR`），单页应用回落到 `index.html`，路径穿越回落到首页。

### 2.6 开源与部署

- 开源所需：`LICENSE`（MIT）、`CONTRIBUTING.md`、`docs/experiments/TEMPLATE.md`（实验记录模板）、给贡献者的 CI（`.github/workflows/ci.yml`）。
- 部署：
  - 一个 Node 进程（PM2 托管）同时提供接口与前端，前面一层反向代理；
  - 推送到 main 由 `.github/workflows/deploy.yml` 部署，只在主仓库运行；
  - 细节见 [DEPLOY.md](../../DEPLOY.md)。

## 3. 验收

1. 虚惊：没有断电，没有人措手不及；为它挪的安排整段计入过度调整；见证者记下虚惊经历、信任下降；事件重放同一哈希（有测试）。
2. 没有虚惊的场景，在默认参数下与 v2 逐字节相同（4 个黄金哈希对照，在升 POLICY_VERSION 之前验证）。
3. 预测跑完自动判定；不认识的指标、同一个分支、写错的方向都被拒绝（有接口测试）。
4. 公开模式：Jev 被拒、种子数与次数有上限、过期数据连同分叉一起删除、精选实验保留（有接口测试）。
5. 广场：先猜 → 揭晓 → 在这里重跑 → 看结果时预测已判定；复制并修改能打开实验清单（有端到端测试）。
6. 生产模式本机演练：前端、深层路由、带哈希的静态资源（长缓存）、接口、路径穿越都符合预期。

## 4. 决定

- **D45 虚惊是事件模式，而不是一种新事件。**
  - 同一轮可以在分支里切换“真停电 / 虚惊 / 不存在”，分叉前的世界完全相同。
  - 否决“另造一种虚惊事件”：做不了同一轮的对照。
- **D46 虚惊的幅度用 Jev 面板在跑实验前量出，照做的变化也进参数，而且所有经历类型一视同仁。**
  - 预注册写了“对信任、照做、查证、担心的平均变化，直接作为规则参数”。
  - 只给虚惊加“照做”会让“虚报 vs 漏报”的比较偏向虚报。
- **D47 经历按次数叠加。**
  - 依据面板里“两次虚惊”那一格：信任 −0.24 ≈ −0.13 − 0.09；照做 −25 ≈ −8 − 15 个百分点。
  - 否决“只看最近一次”：会低估连续失信。
- **D48 年龄分组与走样进标准指标。**
  - “谁被落下”“话传歪了多少”是别人最可能想问的两类问题。
  - 否决“只在脚本探针里算”：演示站上的访客用不到。
  - “第几手”的传话链仍只在探针里：太专门。
- **D49 广场的内容是仓库里的一个 JSON，由脚本从案例定义生成。**
  - 保证“在这里重跑”和实验记录是同一个实验；改卡片就是改代码评审里的一个文件。
  - 否决“在数据库里存卡片”：无法评审，演示站换库就丢。
- **D50 演示站只开放规则模式。**
  - Jev 每次运行都要花钱，访客一多预算不可控；规则模式免费、秒级，已向 Jev 校准过。
  - Jev 的结果以“预先跑好”的形式展示在卡片上。
- **D51 公开模式下关掉自动台词。**
  - 每段传消息的对话都会调用生成模型，访客一多会把总预算烧在装饰上，建镇对话和报告反而用不了。
- **D52 服务器用只读 deploy key 拉代码。**
  - deploy key 在仓库私有和公开时都能用，仓库可见性变化不用改部署。
  - 否决“服务器上放 GitHub token 走 HTTPS”：token 的权限比只读 deploy key 大。

**上线（2026-09-30）**
- 推送到 main 后 GitHub 上 CI 与部署（检查 + 部署两步）都通过。
- 验证到的：本机 `/api/health` 为 200（公开模式限额生效，`jevAllowed: false`）；首页 200；HTTP 返回 308 跳 HTTPS。
- DNS 生效后验证：三个公共 DNS 都解析到服务器；HTTPS 为 HTTP/2 200，Let's Encrypt 证书；带哈希的资源长缓存、zstd 压缩；WebSocket 经反向代理握手 101；内置浏览器里广场与 3D 城市渲染正常、实时推送在走、控制台无报错。

**发布前补的**
- 截图时发现并修复：复盘的“上一个关键时刻”只能往回跳一次，之后停在原地（落点比关键时刻晚 1 分钟，往回找又找到同一个）。端到端测试补了“连续往回跳、再往前跳回原处”的断言。
- README 与文章的配图放在 `docs/assets/`（广场、观察、虚惊之后的反应墙）。

**留下的**
- 访客之间还不能直接分享实验：只能导出文件，贴到 issue 里。
- 广场卡片的文字是手写的：案例重跑后，数字要手动核对。
- 实验清单编辑器是 JSON 文本框：对不写代码的人仍有门槛；表单化留作下一步。
