## 1. 背景与目标

v1 结束时留下三个问题：
1. 转述、注意、效用、信任的常数都是手设的，结论是否依赖这些值无从检验：常数散在五个文件里，改一个就得改代码。
2. 对照实验只能改“怎么发通知”，不能比较“不同的镇”（信任文化、焦虑、关系网）或“不同的心智参数”。
3. 两轮实验里信任会变，但第二轮行为几乎不变，而信任的幅度是手设的。

目标：
- 让“同一座镇换一组参数”“同一套剧本换一座镇”都成为一等公民的实验分支；
- 用这套能力做校准，再做社会实验。

## 2. 设计

### 2.1 规则参数（`packages/sim/src/params.ts`）

`RuleParams` 分六组，覆盖心智规则里的全部手设常数：

| 组 | 内容 | 用在哪 |
| --- | --- | --- |
| `attention` | 注意的截距、各因子权重、各渠道显著度 | `mind/assess.ts` 的 `attentionOf` |
| `mention` | 对话中提起一条消息的截距与权重 | `mind/assess.ts` 的 `mentionOf` |
| `transmit` | 细致度平移、精确时段保真、漏说阈值、焦虑补全“全天” | `info/claims.ts` 的 `transmitSlots` |
| `credibility` | 官方、非官方、口耳相传的可信度斜率；相信 / 半信阈值 | `info/belief.ts` |
| `decision` | 惯性、契合、查证、避损、成本权重，抽样温度 | `mind/reaction.ts` 的 `scoreReaction` |
| `trust` | 信任规则表的 10 条变化量与总幅度 `scale` | `mind/social.ts` 的 `trustVerdict` |

用法：
- `DEFAULT_PARAMS` 就是 v1 的值。所有函数的参数都可选，默认用 `DEFAULT_PARAMS`，所以不传参数的调用行为不变。
- 引擎选项新增 `params?: ParamPatch`，只写要改的项。
  - `resolveParams` 负责合并，未知键和非有限数一律拒绝。
  - 覆盖随快照保存，`Engine.restore` 可以换成另一组。
- `PARAM_KNOBS` 列出敏感性分析扫的 14 个旋钮，每个都带合理范围。
- 不含日程、寻路、库存这类“生活”常数；它们不影响信息与决策，也不在分叉前起作用。

### 2.2 实验分支：换参数、换镇（`experiment.ts`、`apps/server/src/experiments.ts`）

`BranchSpec` 新增两个字段，`ExperimentManifest` 新增一个：

```ts
interface BranchSpec {
  label: string;
  patches?: EventPatch[];   // 已有：改通知
  params?: ParamPatch;      // 新：规则参数覆盖，从分叉点起生效
  town?: TownPatch;         // 新：换一座镇（culture / media / network / population 的部分字段）
}
interface ExperimentManifest {
  // ……原有字段
  params?: ParamPatch;      // 新：整个实验共用的参数覆盖；分支覆盖优先
}
```

运行方式：
- 只带 `params` 的分支：仍从共同分叉点恢复，只是换一组参数。分叉点在第一条消息之前，信息与决策规则在此之前不起作用，所以“从分叉点起生效”等价于从头生效。
- 带 `town` 的分支：
  1. 把补丁合并到底座规格上，经 `normalizeSpec` 后按内容哈希登记为 `sc_<hash>`；
  2. 用同一个 seed 从头跑；
  3. 登记前检查剧本（停电轮次）与底座一致。
- 经典底座是手工小镇，只接受修饰（文化、媒介、朋友数、公告栏）。改人口、跨区关系或亲属比例会被拒绝，并提示先用生成的小镇做底座。

结果记录：
- `ExperimentResult` 升到 `version: 3`；
- 每个分支记下所用的场景 id，以及一行行“改了什么”（`describeBranch`）；
- 复盘的“对照”标签在分支表头显示这些改动；换镇的分支标出“从头跑”。

### 2.3 指标补充与口径修正

每一轮停电新增 4 个指标，在“对照”里默认折叠进“更多指标”：

| 指标 | 含义 |
| --- | --- |
| `allDayEver` | 任何时候信过“全天”的人（谣言触达）。跑的过程中由 `BranchTally` 逐事件记下。 |
| `disbelieved` | 听到了但不信 |
| `verified` | 上网查证过 |
| `intendedOutside` | 家和单位都不在停电区、却改了安排的人（外溢） |

过度调整的口径修正：
- 以前只看被挪动的时段是否与真实停电时段重叠。
- 现在还要看原安排所在的区：原安排不在停电区，就说明是为别的区的停电挪的，整段计入过度调整。

报告事实表写入每个分支的改动与新指标，`REPORT_TEMPLATE_VERSION` 升为 `report_tpl_v2`。

### 2.4 实验脚本（`scripts/lab/`）

| 脚本 | 做什么 |
| --- | --- |
| `towns.ts` | 实验标准镇（60 人）的规格；第二轮停电 |
| `golden.ts` | 重构前后的黄金哈希对照 |

| `jev-pairs.ts` | C2 Jev 对规则：两种心智各跑一遍，并记下每个 Jev 决策请求与答案 |
| `fit-semantics.ts` | C2b 规则语义向 Jev 拟合，逐决策与结果两层检验 |

### 2.5 校准后的心智（params_v2、social_v2、utility_v2）

校准结果见[实验记录](../experiments/20260929-calibration-and-social-experiments.md)第 5 节。落到模型上有四处：

1. **语义因子向 Jev 拟合**（`RuleParams.semantics`）：
   - 用 C2 记下的 2168 个真实决策请求，拟合规则心智的 11 个系数：
     - 各选项契合度的基线；
     - 担心的基线与焦虑权重；
     - 时段模糊或精确时想查证的基线；
     - 发消息的基线。
   - 目标是：同一个请求经同一套效用与抽样后，选择分布的 KL(Jev ‖ 规则) 最小。
   - seed 42–46 训练，47–51 检验。
2. **信任幅度来自面板**（`RuleParams.trust`，`SOCIAL_RULES_VERSION = social_v2`）：
   - 官方信任：每个见证者只归入一类经历，六类与面板的经历一一对应。
   - “澄清过”取代“通知准确”：需要澄清的通知，净增信任只有准确通知的一半。
   - 面板没问到的两条转述规则，按其余转述规则的平均倍数放大。
3. **经历记忆**：
   - 新事件 `experience {agent, outage, kind, text}`，reducer 追加到 `Agent.memory`。
   - 规则心智：最近一次经历按面板结果调整“担心”和“想查证”（`RuleParams.memory`）。
   - Jev：观察里多了 `their_past_experience_with_outages`，因此 `JEV_TEMPLATE_VERSION` 升为 `jev_tpl_v2`。
   - 人物卡、想法、反应墙显示经历（“被坑过”徽章，“记下了：……”）。
4. **缩小挪动与安全的恢复**（`POLICY_VERSION = utility_v2`）：
   - 以前挪动的安排：
     - 按新消息，原安排已不会撞上停电，才提供“恢复原安排”；
     - 只是挪多了（超出所信时段 ≥ 30 分钟），提供“只在所信时段挪，其余照原安排”。
   - 另外，为停电提前关门造成的不便，按关门所依据的消息记到对应的那一轮。

`PARAM_PRESETS.v1` 能把 1、2、3 的参数换回 v1，用于“校准前后”对照。4 是结构改动，不能用参数换回。

## 3. 验收

1. 默认参数逐字节复现 v1：重构前记录的 4 个黄金哈希（经典 ×2、大镇两轮、新区）全部不变；“不传参数”与“传空覆盖”的终态哈希相同（有测试）。
2. 参数覆盖会改变结果，并随快照保存、恢复后继续生效（有测试）。
3. 同一个实验里可以同时有“改通知”“换参数”“换镇”三类分支；换镇的分支从头跑，并记下场景 id（有接口测试）。
4. 非法参数和经典底座上的非法换镇补丁会被拒绝，并给出可读原因（有接口测试）。
5. 校准与社会实验的结果都能在复盘的“对照”里打开，能生成报告。

## 4. 决定

- **D35 规则常数收进一个参数对象，默认值等于 v1。**
  - 覆盖从分叉点起生效，随快照保存。
  - 否决“全局可变配置”：并发实验会互相污染，也破坏确定性。
- **D36 分支可以换参数、换镇。**
  - 换镇的分支从头跑，不共享分叉点。
  - 否决“在经典底座上自动切到生成底座”：那样分支之间差的是一整座镇，而不是一个因素。
- **D37 过度调整按原安排所在区判定。** 否决“只看时间重叠”：会把为别的区停电挪的安排算成必要调整，低估外溢。
- **D38 新指标默认折叠。** 信息量已经偏多（v1 的用户反馈），核心指标仍是原来那 9 个。
- **D39 实验记录单独放在 `docs/experiments/`，假设先于运行提交（预注册）。** 否决“结果出来再写假设”：看了结果再写的假设没有检验力。
- **D40 规则心智的语义因子向 Jev 的真实决策拟合，作为默认值（params_v2）。**
  - 在留出的 seed 上，首选一致率从 62% 升到 82%；结果层面与 Jev 小镇的平均相对差距从 0.29 降到 0.25。
  - 规则模式免费、秒级，是多 seed、多座镇实验的主力；让它尽量像 Jev，比两套心智各说各话更有用。
  - 否决“保留手设值”：C2 显示手设的规则心智系统性地偏爱整段搬走，逐决策只有六成与 Jev 一致。
  - 有 3 个系数顶到了拟合边界：搬走与恢复的基线到了下限，就地变通的基线到了上限。这表示 Jev 强烈偏好低成本的就地变通；边界起了正则化的作用。
- **D41 信任幅度用 Jev 信任面板校准（social_v2）。**
  - 面板：30 位居民 × 6 种官方经历 × 4 种朋友转述经历，逐人与对照配对。
  - 否决“按直觉放大 social_v1”：面板显示“没收到通知被打乱”几乎就是手设的 −0.12，真正设小了的是“通知准确 +0.14”和“朋友说错 −0.20”。
- **D42 经历进入记忆，并影响下一轮的担心与查证。**
  - 面板显示：被坑过的人信任降了，却更愿意照下一次通知改安排（+5 个百分点），也更担心（+0.13）。
  - v1 只有“信任 → 可信度”一条通道，表达不了这种效应。
  - 否决“只放大信任幅度”：那样会得出方向相反的预测（越被坑越不照做）。
- **D43 “恢复原安排”只在安全时提供，并新增“缩小挪动”。**
  - S6 的诊断：澄清让人知道了精确时段，但先按“下午”挪走的安排只能整段恢复（又会撞上停电），于是一直维持着。
  - 否决“把澄清无效当作现实里的黏性”：黏性应该是居民自己的选择，而不是选项缺失造成的。
- **D44 保留现有的 Jev 问法（英文指令 + 中文内容）。**
  - C3：换指令语言只改变 5% 的首选，换内容语言改变 15%；两者都远小于规则与 Jev 之间的差异。
  - 没有真值时，无法判断中文内容还是英文内容更“准”；改动还会让已有缓存全部失效。

## 6. 落地记录

2026-09-29 完成，提交在本地 main（未推送、未部署）。

**做了什么**

平台：
- 规则参数化（D35）；
- 分支可以换参数、换镇（D36）；
- 指标补充与过度调整口径修正（D37、D38）；
- 复盘“对照”：显示分支改动、“更多指标”，列出全部实验并按镇分组。

校准（D40–D44）：
- 语义因子向 Jev 拟合（params_v2）；
- 信任面板（social_v2）；
- 经历记忆（新事件 `experience`）；
- 缩小挪动与安全的恢复（utility_v2）；
- Jev 观察带上过往经历（jev_tpl_v2）；
- 保留现有问法。

实验：
- C1–C4 校准；
- 社会实验 S1–S6，以及探索性的 S4b、S5b、S7；
- 预注册的假设先于运行提交（仓库公开时开发历史压缩成了一个提交，原提交已不可查）；
- 全部实验登记在主库，能在复盘里打开。

**与计划的差异**
- 原计划只“按校准结果调整默认参数”。实际还做了两处结构改动：
  - 经历记忆（D42）：面板显示“被坑后更谨慎”，只放大信任幅度会得出方向相反的预测；
  - 缩小挪动（D43）：S6 的诊断发现选项缺失。
  两处都是实验数据逼出来的，不是事先设计。
- 多出 C2b：向 Jev 拟合规则语义。原因是 C2 显示规则心智系统性地偏爱整段搬走。
- 多出 3 个探索性实验：
  - S4b：S4 在三渠道下触顶；
  - S5b：S5 的第二轮通知太强；
  - S7：检验“失信临界点”。
  都标明为探索性，不计入预注册的判定。

**没做 / 留下的**
- 规则心智的“越不信越要查证”与 Jev 相反，没改：S2 与信任面板两处证据都显示，查证与信任正相关（面板 r = 0.29–0.38）。改了就要重跑全部规则实验，留作下一步。
- 拟合有 3 个系数顶到边界（D40）：边界起了正则化作用，没有放开边界再试。
- 实验结论只覆盖“河分南北”一种骨架、30–60 人、停电一类事件。
- 主库因为存着每个实验的首个 seed 运行，涨到约 0.5 GB；没有做清理工具。

**验证**
- `pnpm check`：类型检查、lint、单元与接口测试（86 个，1 个真实调用用例默认跳过）。
- `pnpm e2e`：18 个端到端测试全部通过。
- 默认参数改为 v2 之前，4 个黄金哈希逐字节不变；改为 v2 后，重放一致、快照恢复一致、分叉前哈希一致的测试照常通过。
- 花费：
  - 本轮真实模型调用：C2 $0.067、C3 $0.03、C4 $0.01、社会实验约 $1.1。
