## 1. 背景与目标

原方案要做一个可观察、可干预、可复盘的微缩 AI 社会。它的一句话立项标准是：说得清"这个人为什么知道这条消息、为什么此刻选这个动作、没选的是什么"。

v0 只交付原方案第 37 页的"首个完整演示"，每一环都是真的：

- 30 个居民在像素小镇里正常生活：作息、吃饭、上班、购物，钱和库存都守恒；
- 政务中心发布"北区计划停电"通知，经网站、推送、公告牌和口耳相传（对话/私信）扩散；
- 居民出现不同但未被预写的反应：查证、改计划、提醒家人、误传、没空理会；
- 停电在 D04 14:00–16:00 真实发生，并产生可计算的"不便"；
- 点任意居民，能还原他收到的版本、读到的片段、理解的槽位、决策候选/因子/概率/随机数、最终行为；
- 在发布前分叉 A/B/C/D 四个分支（网站 / +公告牌 / +推送 / +推送+澄清），对比传播与后果。

### 2.2 时间与调度

- `SimTime` 为整数秒，从 D01 00:00 起算；D01 为周一。
- 场景从 D01 06:00 开始。
- 离散事件调度：任务队列按 `(t, priority, seq)` 排序，同一时刻的冲突用显式优先级裁决。
- 观看倍速：暂停 / 1× / 10× / 60× / 300×，以及单步。单步有两种：推进到下一个事件，或推进 10 模拟分钟。
- 后台"全速"模式专供分支批跑。
- 异步决策遵循"发出时固定观察，按预定时刻提交"：
  1. 请求在 t 时刻冻结 observation；
  2. 在 t + thinkTime 提交（反应决策 180s，通知决策 120s）；
  3. 到提交时刻答案未回，世界等待（slow_world），界面显示"等待决策"；
  4. 超时（真实 20s）或超预算时，写入带标记的规则回退。
- 快照：每 30 模拟分钟一份，内容包含 state、任务队列、挂起的决策请求和 id 计数器。

### 2.4 生活与经济（S1）

**日程。** 每天醒来时按身份模板生成当日计划，时间抖动来自 `rng(seed, agent, "plan", day)`。计划项的形状：

```ts
PlanItem {
  id; start; end;
  kind: 'sleep'|'breakfast'|'lunch'|'dinner'|'work'|'wfh'|'class'|'study'|'shop'|'leisure'|'walk'|'care'|'nap'|'home';
  placeId;
  flexible: boolean;
  needsPower: boolean;
}
```

执行规则：
- 开始时刻不在目标地点就先步行过去，步行时长由 A* 路径长度决定，1 瓦片 ≈ 8 秒。
- 前置条件不满足（未营业、停电、钱不够、满员）时，写 `activity_ended{outcome:'failed', reason}` 并走规则回退。

**钱。** 以整数"分"记账：
- 买东西：居民 → 商户账户。
- 工资：每天收班时由单位付给员工。
- 城外流入：退休金、学生补助、工作室的外部客户收入、供应商补货，都以 `ext:*` 边界账户计。
- 守恒：全部账户（含边界账户）之和恒定；内部账户不得为负。

**库存。** 超市、便利店、咖啡馆、小馆有库存；住户有家庭食物储备。满足 `期初 + 补货 − 售出/消耗 = 期末`，库存不得为负。充电宝库存有限（超市 6、便利店 4），"最后一件"按事件顺序裁决，输的一方记为失败。

**手机电量。** 醒着时每小时掉 4–10%，睡着时 1%。在有电的家或单位时每小时充 30%。电量为 0 时，推送和私信进入待收，充上电后才能收到。

### 2.5 信息：结构化主张（S2，核心）

**主张槽位。** 主张是带槽位的结构，一个主张族（family）下挂多个版本：

```ts
Slots {
  event?: 'power_outage'|string;
  area?: 'north'|'south'|'town';
  day?: number;
  window?: {kind:'exact', from, to} | {kind:'coarse', label:'morning'|'afternoon'|'evening'} | {kind:'all_day'};
  source?: 'gov'|'press'|'org'|'person';
  certainty?: 'confirmed'|'likely'|'rumor';
  advice?: ('charge_devices'|'plan_elsewhere'|'store_food')[];
}
ClaimVersion { id; familyId; parentId?; slots; contentHash; origin: {kind:'publish'|'relay'|'correction', by, channel}; mutations: Mutation[]; createdAt }
```

版本按 `contentHash` 去重。转述边单独记录在 `Transmission { from, to, versionId, channel, t }`，所以血缘是一张有向图。

**新闻。** `NewsItem { id, familyId, headline:{text, versionId}, body:{text, versionId}, publisher, channels, publishedAt, correctionOf? }`。标题版本只含部分槽位，例如 window 只写"下午"；正文含全部槽位。

**渠道与片段。**

| 渠道 | 何时曝光 | 片段 |
| --- | --- | --- |
| 网站 | 看网站时（习惯时段的 `read_news` 活动） | 标题列表；打开后读正文 |
| 推送 | 订阅者发布时手机醒着且有电；睡着则醒来时 | 锁屏标题；打开后读正文 |
| 公告栏 | 步行路径经过公告栏 2 格内 | 海报标题；驻足（打断步行 1–3 分钟）后读全文 |
| 对话 | 同地点的社交时刻：家庭早晚饭、午休、咖啡馆/公园/广场休闲 | 说话人所信槽位（可能变形） |
| 私信 | 通知决策发出，收件人下次看手机时读到 | 发送人所信槽位 |
| 单位通知 | 有权限的管理者调整营业/办公安排后通知员工 | 管理者所信槽位 + 安排变更 |

**七阶段漏斗。** 每个（居民 × 主张族）都记录以下七个阶段：

1. 可达：渠道条件满足；
2. 曝光：exposure 事件；
3. 注意：打开/驻足/听进去；
4. 理解：抽取到哪些槽位；
5. 信念：believe / doubt / disbelieve 及置信度；
6. 意图/行动：改计划的决定及执行结果；
7. 二次传播：转述了谁、用的哪个版本。

没有反应也要写明停在哪一步：未达、未看、未懂、不信、不相关、有意但受阻。

**规则函数。** 函数形式和参数都写在 `packages/sim/src/info/`，版本号为 `infoRulesVersion`。

- 注意：`P = sigmoid(a0 + a1·相关性 + a2·新颖性 + a3·curiosity + a4·渠道显著度 − a5·忙碌 − a6·疲劳 − a7·重复)`。
  - 相关性由槽位与本人住处、单位、计划的交集计算。
  - 这一步是同步的规则判断。
- 理解：片段中的每个槽位按 `阅读深度 × 注意程度 × (1 − 0.3·疲劳)` 被抽取。exact 时段可能被记成 coarse，也可能漏掉。
- 信念合并：
  - 槽位冲突时，按来源可信度 × 确定度取胜；
  - 置信度只为"独立根源"加成，同一根源的多次转述不叠加；
  - ≥0.55 为 believe，0.3–0.55 为 doubt，<0.3 为 disbelieve。
- 转述变形（谣言的唯一来源）：说话人对每个槽位按 `detail` 保留、降精度（exact→coarse）或丢弃。若 window 缺失且 `anxiety` 高，按概率补成 `all_day`，记录 `Mutation{slot:'window', op:'fill_worst_case', because:{anxiety}}`。产生新内容时生成新版本，`parentId` 指向说话人持有的版本。
- 澄清：`correctionOf` 指向原新闻。官方 exact 时段在信念合并中压过 `all_day`；只有接触到澄清的人才会更新。

### 2.6 决策（S3）

**决策种类。**

| 种类 | 触发 | 同步/异步 | provider |
| --- | --- | --- | --- |
| attention | 每次曝光 | 同步 | 规则 |
| relay | 对话中逐个听者 | 同步 | 规则 |
| reaction | 信念形成或变化，且与本人计划相关 | 异步，thinkTime 180s | 规则 或 Jev |
| notify | 对不在场的亲友是否发私信 | 异步，thinkTime 120s | 规则 或 Jev |
| routine | 午饭去哪、休闲去哪等 | 同步 | 规则 |

**reaction 候选。** 由规则生成，6–12 个：
- `keep`：保持原计划；
- `verify`：查网站；
- 对每个受影响计划项：`move:<item>:<替代地点>` 或 `reschedule:<item>`；
- 有权限者：`adjust_service:<place>:cold_menu|close_window|relocate_team`；
- `prepare`：买充电宝或提前充电。

非法候选（关门、没钱、满员、无权限）放进 `rejected`，并写明原因。

**效用与抽样。**
- 效用：`U(a) = Σ_k w_k·f_k(a)`。因子分两类：
  - 规则因子：`avoid`（避开的受影响分钟 × 置信度）、`cost_time`、`cost_money`、`habit`；
  - 语义因子：`fit`、`concern`、`verify_need`。
- 权重 `w` 由特质推出。
- 抽样：`π = softmax(U/τ)`，τ 由 `order` 推出。
- 随机数 `u = rng(seed, agent, kind, familyId, 局部计数)`，按键计算，不按全局顺序递增。这样分支里多出的决定不会让其他抽样错位。

**语义因子来源。**
- 规则 provider：用特质公式近似。
- Jev provider：每次决策发一个请求，包含三个问题：
  - `fit`：choice，对全部候选给出概率；
  - `concern`：score，0–4；
  - `verify_need`：noul。
- 问题模板用英文，state 用结构化 JSON，值可以是中文。

**审计记录。** 每次决策存一份：

```
DecisionRecord {
  id; runId; agentId; t; kind; trigger; observation(摘要+hash);
  provider; model; modelCallIds;
  candidates[{id,label,params}]; rejected[{id,reason}];
  factors{cand:{factor:{value, source:'rule:<id>'|'model:<callId>'|'fallback:<reason>'}}};
  utilities; probabilities; rng{key, value}; chosen;
  commit{at, outcome:'applied'|'invalidated'|'fallback', reason?};
  summary(模板生成，标注"解释性摘要，非内部推理")
}
```

**跨分支答案缓存。** 键为 `sha256(model + templateVersion + canonical(request))`。观察相同就复用答案，差异只来自干预真正改变了信息的人。需要测模型方差时，以 `bypassCache` 显式绕过。

### 2.7 模型接入（OpenRouter）

- Jev：`POST https://openrouter.ai/api/v1/systemone`，`model: "typesafe/jev-1.13"`，记录响应里的快照 id（例如 `typesafe/jev-1.13-20260917`）和 `usage.cost`。
- 生成模型：`deepseek/deepseek-v4-flash`（钉住版本），`reasoning:{enabled:false}`，`usage:{include:true}`。
  - 用途：把对话/私信里交换的槽位渲染成中文台词，只供展示；
  - 文字不回流到状态，也不进入居民记忆；
  - 实时运行时后台异步渲染；分支批跑时不渲染，用户查看时按需渲染并缓存；
  - 失败时用模板句。
- 预算闸：每次运行默认上限 $0.50；累计上限 $3（含开发测试）。超过后自动转规则或模板，并在审计里标记。
- 密钥：`OPENROUTER_API_KEY` 只从 `.env.local` 读，不进仓库，不下发前端。

### 2.8 停电后果与"不便"

- 世界真相：D04 14:00 北区断电，16:00 恢复。它是场景里的世界事件，与新闻是否发布无关。
- 停电时：
  - W07/W08/W09/W10 无法营业。咖啡馆若已切换冷饮餐单，则降级营业。
  - R01/R02 的 `needsPower` 活动失败或中断，例如在家办公、看电视、充电。
  - 北区家中和单位无法充电。
- 不便 = 因停电失败或被中断的计划项数与分钟数，按人、按分支统计。
- 过度反应 = 真实停电窗口之外被取消的计划分钟数，加上为错误信念支出的金额。它用来衡量"整天停电"谣言的代价。

### 2.9 实验与分叉（S4）

```ts
ExperimentManifest {
  id; scenario:'town30'; seed; provider:'rule'|'jev';
  forkAt:'D03 08:00'; until:'D04 20:00';
  branches: {
    A:{channels:['website']};
    B:{channels:['website','board']};
    C:{channels:['website','push']};
    D:{channels:['website','push'], clarification:{at:'D03 16:00', channels:['website','push']}};
  }
}
```

1. 基线运行从 D01 06:00 跑到 forkAt，取快照。
2. 每个分支从快照恢复，只注入该分支声明的干预（通知 N001 在 08:05 的渠道集合；D 分支加上澄清 N002），然后全速批跑到 until。
3. 分叉前的状态哈希必须一致。

对比指标：
- 漏斗各阶段人数与转化率；
- 达到 50% 知晓的时间（未达到则显示"未达到"，不填 0）；
- 版本数和持有扭曲版本的人数（截至 D04 14:00）；
- 不便与过度反应；
- 决策数、回退率、花费、缓存命中。

### 2.12 前端（像素风，统一设计系统）

**视觉语言。**
- 调色板：Endesga 32 的 32 色，城市、UI、图表共用。
- 字体：Fusion Pixel 12px（OFL，`@fontsource/fusion-pixel-12px-proportional-sc`），字号只用 12/24px 的整数倍。
- 圆角为 0，2px 像素描边，阶梯阴影，过渡用 `steps()`。
- 图标：12×12 位图，用 SVG `crispEdges` 画，UI 和城市共用一套；头像和 3D 小人同源生成。

**城市。**
- 相机：正交，yaw 45°，pitch 30°（2:1 等距）。
- 画布低分辨率渲染后最近邻放大；缩放档位就是像素倍数 1/2/3/4。
- 纹理：程序生成 16×16 体素纹理。
- 小人：方块造型，带摆臂走路动画。
- 头顶图标：推送、阅读、对话、查证、刚得知、受停电影响。
- 其他：屋顶可隐藏（露出室内小人），昼夜光照，夜间窗户亮灯；停电时北区变暗并挂横幅；公告栏张贴海报；选中主张族时显示传播连线。

**布局。**
- 顶栏：运行、时钟、播放控制、状态徽章、"发布新闻"、"分叉实验"。
- 左栏 18%：居民 / 地点 / 新闻列表与筛选。
- 中央 54%：城市。
- 右栏 28%：选中居民时显示检查器的六个标签（概况 / 认知 / 记忆 / 关系 / 决策 / 时间线）；未选中时显示社会看板（漏斗、指标、停电状态）。
- 底部：时间轴与版本链，点击可回到当时状态（只读历史模式）。

**弹窗。**
- 新闻编辑器：标题、正文、槽位、渠道、锁屏和海报预览。
- 分叉实验：预设 A–D，显示进度。
- 分支对比：指标表、漏斗条，同一居民跨分支对照。
- 决策详情：候选与淘汰原因、因子及来源、概率条、随机数、执行结果。

**交互一致。**
- 快捷键：空格 播放/暂停，1–4 切倍速，N 发布新闻，F 分叉，Esc 关闭，[ ] 切换缩放。
- 所有可点击元素共用按钮/标签/列表项组件；悬停、选中、禁用三态一致。

### 2.13 测试

- **sim 单元测试**（vitest）：时间、随机数、寻路、reducer、日程、主张变形、理解、信念合并、决策与随机键、不变量。
- **浸泡测试**：30 人、规则 provider、7 个模拟日。要求不变量零违例；每个快照点"快照 + 事件重放"的哈希一致；同一 seed 跑两次终态哈希相同。
- **知识隔离测试**：只给一个人植入秘密主张，其他人的信念只能经由记录在案的转述获得。
- **分叉测试**：分叉前哈希一致；同一分支跑两次结果相同；分支差异只从干预之后开始出现。
- **服务端接口测试**：建运行、控制、发布、分叉、实验，均用规则 provider。
- **Jev/DeepSeek**：录制夹具测试，外加一次真实调用冒烟（`LIVE=1` 时才跑）。
- **E2E**（Playwright）：加载、播放/倍速、选居民看标签、发布新闻、看漏斗、开决策详情、跑 A/B 分叉并看对比，同时截图存档供视觉检查。

## 3. 验收标准

1. `pnpm test` 通过。浸泡测试满足：零违例，重放哈希一致，同 seed 同哈希。
2. 知识隔离：没有接触记录的人对该主张族无信念；每个信念槽位都能追溯到 exposure → comprehension 事件；扭曲版本只能由记录在案的 Mutation 产生。
3. 停电演示在规则和 Jev 两种 provider 下都能跑完。漏斗七个阶段和负面状态都有记录。有居民改计划；有人经转述形成扭曲版本（至少一个 seed 可复现）。"不便"可以算出来。任选一个居民，能看到版本、片段、槽位、候选/因子/概率/随机数/选择、执行结果。
4. A/B/C/D 实验：分叉前哈希一致；对比视图列出各分支的漏斗、50% 知晓时间、扭曲版本持有人数、不便与过度反应。
5. Jev 经 OpenRouter 真实跑通完整四分支实验，缓存命中和回退都有记录。开发加测试的总花费 ≤ $2。
6. 像素风统一：城市、面板、弹窗共用一套调色板、字体、描边和图标。E2E 覆盖第 2.13 节列出的流程，截图人工检查无错位、无非像素字体、无溢出。
7. 关闭浏览器不影响模拟；重连后按 seq 补齐，与服务端状态哈希一致。

## 4. 决定记录

- **D1 范围**：v0 只做 30 人停电闭环，120 人、72 类动作、组织全量延后。原方案第 35 页排期（先扩 120 人、后分叉）与第 37 页（30 人 + 分叉是首个完整演示）冲突，以第 37 页为准。否决：按原排期先扩人口。
- **D2 切片顺序**：S1 生活 → S2 传播（纯规则）→ S3 Jev → S4 分叉。传播结构决定了 Jev 要问什么，所以规则版先把闭环跑通。否决：原方案的"先认知后传播"。
- **D3 结构化主张**：槽位 + 版本 + 转述边。这样知识隔离、谣言机制、澄清送达都能写成断言测试。否决：以自由文本为传播单位，这会让验收无法判定。
- **D4 动作集从演示倒推**：加入修订计划、私信、上下班；去掉转发、刷动态。G2–G5 合成一个"交谈"宏动作，一次性结算交换的主张。否决：照搬第 13 页的 18 类，或做逐轮 LLM 对话。
- **D5 停电后果与不便**：停电作为世界真相执行，不便和过度反应用于量化预先行动的价值与谣言的代价。否决：只看信念分布。
- **D6 存储与进程**：内存权威状态 + 纯 reducer + node:sqlite 事件库，只有两个进程。单一提交顺序下一致性来自内核本身。否决：PostgreSQL + pgvector + 独立 model worker，此时没有瓶颈需要它们。
- **D7 确定性**：按键计算的计数器式随机数、跨分支答案缓存、全速批跑。否决：第 28 页样例里的顺序 `draw_index`，它会让分支错位。
- **D8 语言**：界面和台词用中文；代码和字段用英文；Jev 问题用英文、state 用结构化 JSON。冒烟测试中，Jev 对中文 state + 英文问题的判断合理。否决：全中文问题模板（未评测前不押注）。
- **D9 画面**：正交体素 + 低分辨率最近邻放大 + 像素 UI，用 react-three-fiber。缩放档位 = 像素倍数，保证纹素清晰。否决：2D 精灵图（需要大量手绘素材），或无像素化的 3D。
- **D10 模型接入**：统一走 OpenRouter。Jev 为 `typesafe/jev-1.13`；生成模型为用户指定的 DeepSeek Flash，钉住 `deepseek/deepseek-v4-flash`（$0.07/$0.14 每百万 token，不开推理）。否决：`~deepseek/deepseek-flash-latest` 别名，它不钉版本，违背可复现。
- **D11 Jev 的职责**：只提供 reaction/notify 的语义因子，选择由效用 + 抽样完成。注意、转述、日常动作用同步规则。否决：让 Jev 直接选动作，或对每步走路都做判断。
- **D12 台词只供展示**：生成文字不进入状态和记忆，失败时回退到模板。否决：让台词文本作为传播载体。
- **D13 前端同构 reducer**：服务端推事件，前端用同一 reducer 重建状态。否决：服务端推全量投影，带宽大，且有两套逻辑。

实施中新增或修订的决定：

- **D14 重连下发完整状态**（修订 §2.11 的“按 seq 补齐”）：新连接先收到 `hello{state, seq}`，再收增量事件；前端丢弃 seq 不大于本地的事件。30 人状态约几百 KB，完整下发比补发更简单，并有 E2E 验证前后端哈希逐字节一致。否决：维护按 seq 的补发窗口。
- **D15 城市文字用单一 DOM 叠层**：地点标签、名字牌、对话气泡、停电横幅由一个投影器每帧写 transform。drei `<Html>` 每个都是独立 React 根，卸载时报竞态且开销大。否决：继续用 drei `<Html>`。
- **D16 漏斗逐层嵌套**：理解蕴含注意（只扫一眼标题但记住了内容，也算注意到了），保证“可达 ≥ 曝光 ≥ 注意 ≥ 理解 ≥ 相信 ≥ 改安排 ≥ 行动”，转化率不会超过 100%。否决：注意只算“点开全文”。
- **D17 对话事件写明说出口的版本**：先按对话开始时的信念算出每条转述的版本并写进 `conversation` 事件，再逐条落地。台词渲染与气泡都依赖它。否决：对话事件只记“提没提”，版本留给之后的转述事件。
- **D18 台词校验加严**：事实里没有精确时刻时，台词不许出现任何钟点（含“两点”这类口语）；也不许凭空出现“全天”。否决：只校验 HH:MM 形式。
- **D19 观看倍速与快进**：倍速改为 1×/10×/60×/300×/1800×，加“快进到…”关键时刻（发布前后、停电前/中、来电后）。原因：60× 下两天要看 48 分钟，演示和验收都太慢。否决：只靠 300×。

- 真实调用：经 OpenRouter 跑通两次 Jev 四分支实验（seed 42 / 2026）：以 seed 2026 为例 222 次 Jev 决策、0 错误、0 回退，平均延迟 700–780 ms，D 分支 59 次中 38 次命中跨分支缓存；全程 448 次 Jev 调用 0 错误。DeepSeek 台词渲染 28 条，全部通过校验（其中 20 条生成于 D17 修复前，只是闲聊）。

与方案的差异（原因见 D14–D19）：重连下发完整状态；城市文字改用 DOM 叠层；漏斗嵌套；对话事件写明版本；台词校验加严；倍速与快进。

结果观察（合成轨迹，不是结论）：
- 仅网站（A）时，半数人相信要约 22–24 小时；加推送（C/D）时约 1–4 小时。
- 停电时措手不及的人数：A 为 1–7 人，C/D 多为 0–1 人。
- “全天”谣言由焦虑补全机制自发产生：多数 seed 下是 0–4 人，seed 7 的 A 分支有 15 人。
- 过度调整主要来自标题只写“下午”：人们挪走的是整个下午，而不是 14–16 点。
- 分支间差异受 seed 影响明显，需要多 seed 才能下结论。

没做 / 留下的：
- 120 人、72 类动作、组织全量、社交信息流、多 seed 统计面板、生成模型决策策略、关系与信誉的长期演化（均按范围延后）。
- 手机电量只做了简化模型；打断中的活动不能被“挪走”，这类候选会被判不合法。
- 场景只有 town30 一个；E2E 不覆盖真实 Jev 路径（避免花费，由脚本单独验证）。
- S3 计划的“约 50 题中英对照小评测”没做：目前 Jev 问题模板是英文 + 中文值的 state，只凭冒烟与实验里的判断看起来合理，未量化比较。
